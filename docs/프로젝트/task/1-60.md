# 1-60 — 타임라인 핵심 압축 (중요도 토글 + 동일날·topic 그룹핑)

> **분야**: 1 (시스템)
> **담당**: Opus
> **기간**: 2026-04-26 → 2026-05-14 (MVP)
> **중요도**: P2
> **관련**: 1-50 (importance 점수 인프라), 1-45 (Tesla 이슈 DB)

---

## 배경

테슬라 대시보드 섹션 08 "마일스톤 타임라인"이 85건 이벤트를 단일 리스트로 노출. 데이터가 쌓일수록 시각적 잡음 증가 — 사용자가 "지금 중요한 5개"를 즉시 식별 불가. 1-50에서 추가된 importance_score(0~20)와 importance_level(core/important/all) 분류가 있는데 UI가 활용하지 않고 `important`만 일괄 표시 중. 같은 날 발생한 여러 이벤트(예: 결산일 + Robotaxi 발표)가 시각적으로 분리돼 시점 단위 파악도 어려움.

## 결정 사항

| # | 결정 | 이유 | 대안 |
|---|------|------|------|
| 1 | 토글 3단계: 핵심(core) / 중요(important) / 전체(all) | 1-50 importance_level 3분류 그대로 활용. 사용자가 깊이 선택 | 슬라이더 (거부: 임계 직관 부족), 2단계 (거부: 정보량 손실) |
| 2 | 기본 선택은 "중요" | 첫 진입에서 정보 풍부하면서 노이즈 없음 — core는 28건 너무 압축, all은 85건 너무 많음 | core 기본 (거부: 정보 부족), all 기본 (거부: 잡음) |
| 3 | 동일 날짜 이벤트 그룹핑 | 같은 시점 발생한 이벤트를 한 카드 그룹으로 묶어 시점 단위 인지 강화 | 리스트 평면 유지 (거부: 시점 단위 파악 어려움) |
| 4 | topic별 색상 띠 (좌측 border 3px) | robotaxi/fsd/optimus/4680/megapack 5개 핵심 토픽을 색으로 즉시 구분 | 배지만 (거부: 시각 스캔 약함), 풀 배경색 (거부: 가독성 저하) |
| 5 | thesis_side에 따른 배경 그라데이션 | bull/bear 테제 영향이 한눈에 보이도록 — 우측으로 페이드 | 풀 배경색 (거부: 텍스트 가독성), 배지만 (거부: 약함) |
| 6 | counts 응답을 API에서 제공 | 토글 버튼에 건수 표시(`핵심 28`) — 사용자가 클릭 전 결과 예측 가능 | 프론트에서 별도 호출 (거부: 라운드트립 비용) |
| 7 | 상대 날짜 표시 (D+5, +2M, -3.2Y) | 절대 날짜 옆에 현재 기준 거리감 함께 표시 — 시점 인지 보조 | 절대만 (거부: "언제쯤?" 즉답 어려움) |
| 8 | 그룹별 상태 점 색 (past=green / soon=blue / planned=gray) | 과거/임박/예정 3분류로 시간 흐름 시각화. 30일 이내를 "임박"으로 정의 | 4분류 (거부: 인지 복잡), 점 없음 (거부: 흐름 시각화 손실) |

## 흥미로운 발견

`importance_level=important` 응답이 85건으로 `all`과 동일 — 백엔드 분류가 important를 "core+important"로 묶고 있어 사실상 필터 효과 없음. 토글이 의미를 가지려면 important를 별도 분류로 분리하거나(core 28 / important 30 / all 85), 또는 토글 라벨을 "핵심(core) / 전체(all)" 2단계로 단순화해야 함. 후속 결정 필요.

## 후속 작업

- 백엔드 important 분류 분리 — 현재 important=all이라 토글 무의미
- 그룹 접기/펼치기 — 5건+ 이벤트가 한 날에 몰릴 때 기본 접힘
- 토픽 필터 칩 — 색상별 클릭 필터 (Robotaxi만, FSD만)
- 시간 축 줌 (D/W/M/Y)
